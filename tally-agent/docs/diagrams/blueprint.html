Tally Agent Blueprint

How a question typed by a CA firm's staff member becomes an answer from Tally. It shows where each piece runs, what data crosses each boundary, and what the local AI is and is not allowed to see.

The AI never sees client detailsNames, PAN, GSTIN, phones, emails and account numbers are swapped for placeholders like [PARTY_1] first.
The AI never writes SQLIt picks one of 14 reviewed reports and fills typed parameters. Nothing else can run.
The AI never produces a numberPython computes every figure. An AI explanation is dropped unless its figures appear in the data.
01

The whole system

Everything runs on the office PC that runs Tally. Only Caddy is reachable, and only over Tailscale. The agent, model, cache and database sit on internal networks with no route to the internet.

02

Keeping a copy of Tally

Answers never touch Tally directly. A copy is refreshed about once a minute, and every answer says how old its data is.

03

Answering one question, step by step

Follow “How much does Acme owe us?” through the system. The amber lane is the AI: only placeholders ever reach it. Real names cross only into Redis (to remember the swap) and PostgreSQL (to run the report).

04

What the AI never sees

Two detectors run before any text reaches the AI. Patterns catch identifiers. A dictionary built from the company's own ledger list catches names, which no pattern could. Placeholders are stable within a conversation, so the AI can still reason about “[PARTY_1] versus [PARTY_2]”.

05

Who can touch what

Each database login can do exactly one job. An arrow that isn't drawn is a permission that doesn't exist.

06
